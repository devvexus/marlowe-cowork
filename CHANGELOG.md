# Changelog

All notable changes are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Green main and follow-ups

- Headless: a message sent while the turn is running, or while its ask is still starting the turn, steers it instead of queueing a second turn (a steer no longer resends the run options, which made the daemon queue it).
- Per-role tool table re-pinned for the tuned tool descriptions of the first-try probe (28b400e); no role's tool list changed, token costs rose by 11 (guide, researcher, scout) to 50 (engineer, lead, integrator, workflow) per role.

### Review pass over the live-progress batch

- A short phase on the activity line now carries the turn's running time (`calling the model · 2.6s`), so a remote model's silent wait before its first frame ticks instead of sitting on a static label; the read-to-think line sheds the thinking rate, then the count, before it drops the read at narrow widths.

### Live phases (protocol and instrumentation)

- **One event family for every named step** (`marlowe_proto::phase`): `Event::Phase{kind, state, stage, done/total, rate, ms, est, detail}` for sending, setup, admit, prompt, recall (per stage), fit, compaction, wire and the memory-write tail. `Start`/`End` are ordered and replayed; `Progress` goes through `Bus::publish_ephemeral` (seq 0, not in the ring, never drops a client). Additive: no `PROTO_VERSION` bump, unknown events are skipped by old readers, unknown kinds decode as `Unknown`.
- `Recalled` also carries `total_ms`, per-stage `stages` and `abstained`, and is sent when nothing was recalled. `Event::TurnTimings` (spans, TTFT, harness overhead `enter_to_wire_ms` / `token_to_bus_ms`) goes out just before `TurnFinished` and is stored per turn (`turn_timings` table), replayed on `StoredTurn.phases`/`numbers`. `Request::Ask` takes the client's `client_ms` (Enter).
- **Retrieval observed, not changed.** `StageProbe::progress` (default no-op) is called at chunk boundaries in dense, gate and rerank; the Mind's `LiveProbe` times stages (the clock lives there, not in `marlowe-memory`) and streams them throttled to 8 ms. A test asserts the injected set, scores and order are identical with the live display on and off.
- Agent loop: `AgentEvent::{Phase, CallStarted, FirstToken}`; compaction reports estimated progress and no longer fails silently (`End{detail:"failed"}`). The Mind's write tail (`MindEvent`) reports ingest, embed and index.

### Live phases (provider timings, load meter, prefill estimate)

- `Usage` carries the engine's own `prompt_eval`, `load_ms`, `prefill_ms` and `decode_ms` (Ollama's `*_duration` fields, ns to ms; other providers leave them `None`); `StreamEvent::Sent` marks the request leaving, after the model metadata and body. Old frames still parse.
- The loop closes `Wire`/`prepare` at the send and opens `Prefill` (our prompt estimate, `est`); `Usage` ends it with the engine's counts, ms and rate, so the turn's `read` (new, cached, ms) is real. A failed call still closes it.
- The daemon's `live::Watch` thread (alive only while the engine is silent): cold-load progress from the runners' GPU-memory growth against the planner's predicted bytes (`est` total, never full before it ends, no bar without per-process data), prefill progress from the stored `prefill_tok_s:<model>` (capped 99%, nothing without a stored rate), and `waiting for the GPU - crew run <id>` only when a crew run streams on the same model. Prefill and decode rates are re-measured after every call into `hw_calibration`.
- Spans start where their `Start` landed; `Load`, `Prefill` and `Wire` stages nest under `Wire`.

### Live phases (frame engine)

- **The screen draws at the display's refresh rate while anything is live.** `marlowe_os::console::display_refresh_hz()` (primary monitor, `EnumDisplaySettingsW`; 0/1 or no answer is 60) sets the rate; `marlowe-tui/src/pacing.rs` decides when a frame is due: the first event after a quiet spell draws at once, a burst becomes one frame per refresh, a live turn or the voice ticks at the refresh rate, a still screen once a second, and the boot keeps its 30 fps. A classic console (no `WT_SESSION`) is held to 60; the setting `max_fps` (or `MARLOWE_MAX_FPS`) lowers it for a battery. The process asks Windows for 1 ms timer granularity while the UI runs, so a 7 ms wait is not rounded to 15.6 ms.
- **A live frame re-lays out only what changed.** The transcript's rows are cached per entry (`layout_cache.rs`) under a key of the entry's content, fold state, blank-row gap, live flag, width, theme and an edit's diff; a streaming frame lays out the last entry only, and only the rows on screen are copied out. Typeset images are applied to those rows after the cache, so a formula arriving needs no invalidation. `State::no_layout_cache` lays everything out every frame; a test draws a streamed session both ways and asserts the same screen, cell for cell. `Emitter::frame` no longer copies the screen when no image is on it, and a changing live row never re-sends an image.
- `tests/frame_cost.rs` measures a 120x40 frame over 252 entries (maths, code, diffs, reasoning); see the numbers in the stage report. Nothing in `theme.rs`, the boot or the markdown output changed.

### Live phases (the live strip)

- **Two rows under the output say what the turn is doing, from Enter to the last token** (`marlowe-tui/src/live.rs` state, `render/strip.rs` drawing). Enter puts the message and `sending` on screen in the same frame and stamps `Ask.client_ms`. Row one is the activity line: `reading ~8.2k tok · ~1,900 tok/s ━━━╺━ ~62%` (estimate, `~`, no bar or rate without a stored rate), which at the first token becomes `read ~8.2k · ~1.9s  ›  thinking 4.1s · 312 tok · 76 tok/s` on the same row and loses its tildes when the engine's own numbers arrive; a later step reads `read +1.2k (8.0k cached) · 0.3s`. It also names waiting (`waiting for your approval`, `waiting for the GPU · crew run b8ee`, amber) and tools (`bash cargo test · 12.0s`). Ticking numbers are fixed width.
- Row two carries recall (`recall · dense 2,940/4,198 · 1.9M/s`, each stage queued so it is drawn for at least one frame however fast it ran), a cold load (`loading dusk-27b ━━━╺━ 6.1 / ~13.1 GB`, then `✓ loaded ... 6.2s`), compaction (`compacting 28.1k → … ~312/4,096 tok`, then the result or a red failure) and the memory write (`+1 memory · embedded · indexed ✓`, outliving the turn briefly). Height is two rows whenever it is up and depends on state only; it sits right under the last line, at the pane's bottom once the text fills it, and when it goes away the text stays where it was.
- The reasoning header keeps the read (`▸ read 8.2k · 1.9s  ›  thought 4.1s · 312 tok · 76 tok/s`, one row, shortened to `8.2k/1.9s` then dropped by width); the recall line keeps its stage timings (dim labels, amber numbers; `0 memories · abstained` when the gate declined); with reasoning open (^t) each recall stage and the turn's measured phases (with `enter→wire` and `token→screen ~`) get rows. A reopened session shows the stored read and timings.
- Tools are green, not blue: the theme has no blue, and `theme.rs` is locked. Snapshots changed only where the old `▸ thinking…` row became the strip, and the optimistic message appeared. `frame_cost` now measures the strip busy.

### Live phases (init moments)

- **Shutdown as the boot in reverse.** The daemon publishes `Phase{Shutdown}` steps as they happen (`pause` with the runs in flight, `unload` per model with MiB freed from a before/after runner-memory reading and no byte count without one, `save`, `journal`), then `ShuttingDown`. A quit that stops the daemon now sends `Detach` and stays connected: the TUI shows each step, then `Goodnight, <address>.` from the profile (never hard-coded), and prints that line to the shell. Any key skips; a daemon that announces no close within 1.5 s (another window, keep running) or none within 20 s does not trap the user. The window-close handler path is unchanged.
- **Research channels.** `ChannelRegistry::search_observed` reports `ChannelEvent::{Retrying, Done, Failed}` (the playbook adds `Online` at the start of a wave) through `ResearchIo::search_observed` and `ResearchHost::channel`; the supervisor forwards `Phase{Channel}`. `arXiv ··· 14 ✓`, `Semantic Scholar ··· 429 retrying ⟳`. Results are unchanged by the observer.
- **Crew spin-up.** A run emits `Phase{Spinup}` as sandbox, tools (the role's count), budget and model (first resolve) really end; the transcript shows one line, `spinning up analyst ··· sandbox ✓ · 14 tools ✓ · budget 600k ✓ · model ✓`.
- One line shape, `SeqLine` (`render/seq.rs`), shared by the boot, the shutdown and these in-transcript sequences; a test pins the boot's lines cell for cell. The boot's pacing and look are untouched.

### Web search off OpenRouter

- **`web_search` and deep research never use a paid API.** The tool searches through the keyless web channel research uses (SearXNG at `research.json` `searxng_url`, else DuckDuckGo lite) and says plainly what to run when none answers; the OpenRouter search backend, its model setting and `HostedSearch` hookup are gone. `hosted_search` in an old `research.json` still parses and is ignored.

### Build disk cap

- **Build folders can no longer grow without bound.** `target\debug` reached 300 GB (1,311 stale `.pdb` files of up to 800 MB) and one M4.6 worktree's build folders 590 GB; about 900 GB of stale build output was deleted. Dev and test builds now carry line tables only (dependencies none), so a test's `.pdb` is a few MB.
- `scripts/cargo-idle.ps1` checks the build folder at most every 30 minutes: over 60 GB (`MARLOWE_TARGET_CAP_GB`) it drops the incremental caches and every artifact hash but the newest two per crate, and as a last resort the debug folder; worktree build folders (`MarloweCowork-*	arget*`) not built in two days are deleted. Cargo rebuilds anything missing, so a prune only costs build time.

### First-try probe on the GPU

- **Ollama gets typed tool schemas by default.** The probe (62 cases, dawn:9b and dusk:27b-super, `eval/tool_probe/results/SUMMARY.md`) showed typeless schemas make dusk nest every value (`{"path": {"path": ..}}`): 10.5% strict against 54.8% typed; dawn was level (51.6% / 50.0%). Typed costs about 1,000 prompt tokens on the conductor surface (measured 1.25x chars/3; typeless 1.09x). `MARLOWE_OLLAMA_TYPED_TOOLS=0` sends typeless.
- **Descriptions tightened** for grep, symbols, references, hover, project, bash, powershell, monitor, enter_plan, enter_worktree, ask_user, agent and dispatch; strict first-try on those cases went from 2/30 to 13/45 (dawn) and 8/30 to 19/45 (dusk). `specs_a15.json` regenerated from `compact_specs.json` by design (grep, bash, powershell).
- Probe grader: the edit tools' read-first state gate is no longer counted as a bad call.

### Tool surface, core: nothing hidden, a forgiving layer

- **Changed.** Every built-in of the host's detected groups is listed on every window; the `tool_search` that hid 44 of them behind a 32k window (and held their persona blocks back) is gone from `marlowe-exec`. `tool_search` now exists only in the MCP host, only when MCP tools overflow their share (more than 20, or past the tools slice minus the built-ins listed): its description says it loads tools from the connected MCP servers, names them, and carries a signature index (`mcp__srv__tool(a, b?: int) - first 8 words`; past the share it groups by server, then keeps names only, never dropping an argument name). A direct call to any `mcp__server__tool` runs without loading it. Listed MCP tools are compacted (first-sentence descriptions, no schema noise, no "(MCP server X)" suffix); the full server schema is what calls are validated against. With MCP tools present the prompt tail gets one line (`Tools from MCP servers (mcp__server__tool) - call one directly by name, or tool_search to load its schema.`; without overflow, that they are listed and callable by name).
- **Changed.** `PrefixBudget::for_window`: up to 48k total 12,500 (persona 2,000, tools 7,000, instructions 1,500, profile 300, repo map 800, skills 400, style 200, tail 1,000); 48k-200k total 20,000 (tools 10,000); 200k and more total 34,000 (tools 16,000). - **Added.** The forgiving layer (`marlowe-agent/src/args.rs`): tool names resolve exactly, then case- and separator-insensitively (`WebFetch`, `web-fetch`), then through the permanent legacy table for merged names (`paper`, `job_*`, `todo_*`, `cron_*`, `schedule_wakeup`, `list_agents`, `ci_status`; inert until the target tool exists) and `server__tool` / `server.tool` for MCP, in the loop before middleware, so transcripts and approvals show the canonical call. The first `before_approval` of every agent (conductor, subagents, crew) normalises arguments against the spec the model was shown plus per-tool `ArgRules` (aliases, op folds, enum spellings, requirements, example, see-also; `marlowe-exec/src/specs/rules.rs`): key spelling and aliases, generic synonyms, a URL or arXiv id under the wrong key read as `url`, one stray key paired with one missing required key, lossless type coercions, enum case and unique prefix. A call it cannot fix is answered without asking or running, with the exact signature, an example and a see-also line (`web_fetch was not run: missing `url`; unknown `query` ("min-p sampling" is not a URL).`); the same call twice leads with the example. Free text, units and missing values are never touched; unknown keys are an error, not dropped; MCP tools get only lossless coercions and their own `required`. A renamed key is told once per tool and key on the result, and every rewrite is kept in the session for `/context` and the probe.

### Deny, and tell Marlowe why

- **Added.** The approval modal has a fourth-or-fifth option after Deny, `w deny, and tell Marlowe why` (key `w`, or select it and Enter, or click): it turns into a one-line input, Enter denies with the reason, Esc returns to the options, an empty reason is a plain deny. `Request::Approve` carries an optional `reason` (serde default, omitted when none, so old clients and stored data still parse); `ApprovalDecision` is unchanged. The daemon keeps it per approval, the asking gate hands it to the agent loop through `ApprovalGate::denial_reason` / `RunApprovals::denial_reason`, and the model gets `The user denied this call and said: "<reason>". Do what they said; do not retry the call unless they ask.` (clipped to 600 characters, whitespace folded; the text still opens with "The user denied this call", which the trajectory export and `permission_denials` match on). Works for the conductor, its subagents, and crew runs' tool calls and test commands. The Conversation shows `you told Marlowe why: ...` dim under the tool line.

### Stopping a run is easy to find

- **Added (tui).** The Run view header shows a red `■ stop run` while the run is active, clickable (`Target::StopRun`); `x` is an alias of `c`; the footer leads with `x stop run` in red. The workflow view has the same control. Both ask y/n: "Stop this run? It ends now; its transcript stays." and "Stop this workflow? Running agents stop; finished agents’ results are kept for a resume." Words typed in the steer box are never read as commands, so "cancel" there still only steers.

### Background work the conductor can see

- **Added.** At the start of a turn the conductor gets one `<system-reminder>` in the turn tail (not the system prompt, so the cached prefix is unchanged) listing up to five active crew runs, workflows, shell jobs and monitors from any conversation, with `task_stop <id>` and `task_list` named. It is sent on the first turn and again only when the active set or a status changes, read from the conversation's own history.
- **Changed.** `task_list` lists this conversation's tasks and every active task from other conversations (tagged "other conversation"); `all: true` adds their finished ones. A workflow stays one `wf_*` task; its agents are not tasks and `task_stop` of the `wf_*` id stops the whole workflow (tested in `marlowe-daemon/tests/crew.rs`).

### Thinking-only turns

- **Fixed (conductor).** A step that only thought (reasoning, no text, no call) ended the turn silently. The loop guard now sends one `EMPTY_NUDGE` per turn ("You ended your turn without writing a reply. Write your answer to the user now."); crew steps keep their own retry in `playbook/agent.rs`. If the model still writes nothing, the Conversation shows a dim `ended without a reply` line for a finished turn that showed no prose, note, file or job output; no text is invented or stored. Not done: keeping the thinking-only step across a reload would put a thinking-only assistant message into what providers are sent, so it is left out.

### Run view transcript

- **Fixed (crew).** A role-card run is one step, and its calls were only checkpointed (`crew_run_calls`) until that step ended, so the Run view said "no steps yet" while the rail showed step 22, and a paused, interrupted or failed run never showed what it did. `Supervisor::transcript` now adds each open step after the finished rows, built from its checkpoints with the same line format (`message_lines`), carrying the row the runner reserved for it, its action "stopped here" plus the run's note when no thread is working on it. The runner streams `▸` tool starts and `↳`/`✗` results as text deltas of their own lines, so a model that mostly thinks and calls tools shows progress. The Run view no longer clips the last (open or only) step to its tail; earlier steps still keep six lines.
- **Fixed (crew).** Open-step numbers no longer follow "max finished row + 1" in checkpoint order, which disagreed with the runner's live rows when parallel steps finished out of order and made the TUI push duplicate rows. Each per-call checkpoint now stores the row the runner reserved for its step (`crew_run_calls.row`, migrated in), and `transcript` uses it; checkpoints from before the column fall back to counting up.

### M2.6 Profile in context

## M2 Total Recall — integration — 2026-10-09

### Added
- `marlowe-mind`: the memory service. One actor owns the profile (journal, beliefs, vectors). The embedder and reranker load lazily and unload after 10 min idle. A coalescing embed queue fills vectors in the background. A sealed BeliefStore snapshot means boot derives only the journal tail. With models missing it runs degraded (lexical recall only, no auto-injection) and says so. `import_legacy` copies the old profile, verifies its chain under the old key, and replays memories with their original dates and trust. It is idempotent and never writes to the old directory.
- Injection: `select_for_injection_filtered` with the dense query vector, cross-encoder rerank at `RERANK_BUDGET`, the frozen gate and the declared operating point, filtered to global plus current-workspace beliefs. Every injection is journalled (`MemoryInjected`).
- Daemon: a `MindMemory` hook (inject before a turn, emitting `Recalled`; user and assistant turns ingested). Memory tools `remember`/`recall`/`forget`/`correct` are composed with the session tools. Memory requests, the `LegacyAvailable` offer after Welcome, and an episode summary when an idle session is evicted.
- Proto: `MemorySearch|Forget|Correct|Stats|Probe`, `ImportLegacy`, `LegacyStatus`. Matching events, including `Recalled` and `MemoryProbed`.
- CLI: `marlowe memory search|stats|probe|forget|correct|import|bench`. `ask` prints the dim `⋯ recall · N memories` line. `marlowe --eval-adapter` is restored, with `tools/score_longmemeval.py` and `tools/recall_at_k.py`.

### Changed
- `marlowe-memory` (retrieval numerics unchanged): maturation by trust class on the product path. User-asserted beliefs are live at once; agent, web and untrusted lineage keep the 6 h window, and the eval `ingest()` path stays `Uniform`. BM25 term statistics are cached, bit-identical to the old path (tested). Added kind, scope, speaker and source tags, and a provenance accessor. Assistant prose is never auto-injected. Tombstoned memories drop their vectors.

### Security
- An auto-injected memory with untrusted lineage now taints the run, the same way an untrusted `recall` already did. Before this, a later `remember` or `correct` was written as inferred, and the post-untrusted-read approvals were skipped. `MemoryHook::before_turn` returns a `Recollection` (blocks plus an `untrusted` flag), and `Injection.floor` holds the lowest trust among the injected memories.
- `forget` follows the same trust rule as `correct`. `Mind::forget` takes a `Provenance` and refuses a caller whose trust is below the memory's. When the conductor tries to forget a memory that outranks the run, it asks the user first, and runs with the user's authority if allowed. `MemoryForget` from a client counts as the user.
- An episode summary of a tainted session is stored as untrusted (`Mind::write_episode(.., tainted)`).
- Session taint is stored in `sessions.tainted`, migrated in place, and set again on reload. Taint from an untrusted `recall` or an injected memory no longer disappears after idle eviction or a daemon restart.
- Forgetting writes the snapshot and vector file again straight away, so neither file keeps the forgotten text. The pre-release embedding cache (`<home>\cache\embeddings`), which stored query vectors and vectors of forgotten text, is no longer used and is deleted on open.

### Fixed
- Auto-injection no longer scores candidates that have no vector as dense 0. Up to 64 missing vectors are embedded before an injection. With more missing, injection abstains with `memory index warming (k of n embedded)`.
- Belief vectors persist in a sealed `beliefs.vectors` file next to the snapshot, tied to the embedder's pinned digests and each belief's text. Boot no longer re-embeds the whole store.
- A failed background embed step puts its work back in the queue and retries after 30 s. Before, it cleared the queue for the rest of the process.
- Only a missing or digest-mismatched model puts memory into degraded mode for the rest of the process. Other load failures, such as a file locked by a scanner, are retried the next time the model is needed.
- Boot cost follows the journal tail, not the whole history. The snapshot records the journal signature at its watermark (`Journal::open_from_checkpoint` verifies only from there on), and the tail is folded through a ranged, streaming `Journal::replay_after`.
