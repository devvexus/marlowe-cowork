# Changelog

All notable changes are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

- **Every sentence a writer writes cites a claim, and a writer with nothing to say says so.** Constrained decoding now requires at least one claim per sentence (dawn left them all empty and a section failed), so an unsupported sentence is one the audit can check and cut; a writer that returns no sentences gives "Nothing the run read answers this." instead of a failed section.
- **Report writers cite the claims they are shown, numbered from 1.** A 9b writer cited list positions (0, 1, 3) of claims shown as C10, C41 and C53, every number was unknown and two sections of a live report failed. Writers now see their claims numbered 1 to n, constrained decoding allows only those numbers, and code maps them to the report's numbers.
- **The engine never runs a model with a window under 16k per agent.** When the GPU has room for the weights but not for a 16k window (or the model's whole window, when smaller), the model stays on Ollama, which splits it and gives it a usable window.
- **A project's second model is refused when it would share the engine with the conversation's.** Marlowe's llama-server serves one model per process, so two engine models would swap on every change of role, reloading weights and losing the conductor's prompt cache; the project runs on the conversation's model and says why. The conversation's own load counts as the start's one load, so a second model that also needs loading is refused instead of loaded beside it.
- **Claims keep their place in a report.** A claim kept on its page's subject ("second on CorpFin, behind Kimi K2.5" on a Qwen page) reaches that subject's section and may be cited there; a word that only starts a sentence, or a possessive, no longer becomes a subject of the objective.
- **`dispatch` no longer offers the research roles when projects are live.** `researcher`, `scout`, `compressor` and `verifier` left the role menu and a call naming one is told to start a project with `manage_project`.
- **A project that cannot start for a reason a model will not mend is marked failed**, not retried every few seconds; a project whose conversation is gone runs on the conductor's model.
- **Projects in the terminal: a reopened project and a project that ends mid-reply.** A reopened project's old result leaves the transcript while it runs and settles again where it ends, keeping the first run's relay text; a project ending while a reply streams settles after the reply, so the reply is not split. Employees held for the GPU or memory are shown as waiting with the reason (`◌ 3 waiting for the GPU`) and counted apart from those in a call. A daemon that runs no projects is asked once and its answer is never flashed.
- **Projects appear in the terminal.** A running project is one live entry at the end of the conversation that narrates the run in the boot sequence's voice (phase lines with dotted leaders, the agents in flight, the sources and claims counted so far) and settles into a result entry where it ends, folding the relay news that told the same story; the plan card and every checkin card sit inline under the conductor's question with an amber left rule and answer by key (`a` approve, `r` revise opens the composer, the option's letter, `x` cancel), by click, or from the CLI; `alt-p` goes to the project that needs you, a key on a finished entry opens its report in the reader with its path, and the board's first section lists the projects (glyph, title, elapsed, phase counts) where it listed the crew. Drawn only from the project's generic view-model and display hints; the in-flight blue `#7fa8dd` joins the theme. A strong run inside emphasis in a report no longer leaves asterisks.
- **A project can run its employees and its lead on other models (`projects.model.employee`, `projects.model.lead`).** Both default to the conversation's model, so no second model loads; set in `settings.toml` (`[projects.model]`, user settings only, never a repository's), e.g. `employee = "marlowe-mini:4b-super"`. A named model runs through the crew's slot pool like any crew call, and is admitted against the GPU like any load (one load at a time, none at boot); if it does not fit, is not loaded where nothing may load, or is unknown, the project runs on the conversation's model and says so once in the conversation.
- **A project's employees wait for the GPU and for memory as a crew run's calls do.** A call to a local model is held while another process is computing on the GPU (the employee shows as waiting, "waiting for the GPU") and while Windows is short of commit memory, and fails with the reason if memory stays short; only then does it take one of the crew's shared slots.
- **A project's meters move while it runs.** `metrics.cpu_pct`, `gpu_pct` and `vram_mb` were always 0; the engine now reads the Sentinel's GPU report and this process's processor share every two seconds, writes only changes (coalesced patches), and returns them to zero when the project parks or ends.
- **A project left running by a closed Marlowe no longer waits for your next message when no model was loaded at boot.** A watcher looks every five seconds and starts it as soon as a model is loaded or hosted (it loads none itself); your next turn still starts it at once if that comes first. Two starts of one project at once now make one engine.
- **`dispatch deep_research` is retired; research is a project.** The playbook, its plan approval (the Run view's plan panel and editor, the banner, `marlowe crew plan`), stage strip and report accept are gone from the crew, the wire, the TUI and the CLI, along with `tools/research_produce.py`; `dispatch` offers only `build`. A `dispatch` that names `deep_research` is told in one sentence to start a research project with `manage_project`; a run stored under it still opens as a plain result, and one left unfinished at boot ends as failed with that sentence. `research.json` still parses its old `auto_approve_under_tokens` and `fetch_concurrency` keys and ignores them.
- **The built-in `web-research` team task is retired; research is a project.** Its script, its place in the saved-task list and its tests are gone (`code-review` and `simplify` remain); the workflow guide's example is renamed `source-check`. A model that still asks for `team{name:"web-research"}` where projects run is told in one sentence to start a research project with `manage_project`.
- **A claim about one model no longer lands under a question about another.** Found live (run m6): a DeepSeek "V3.2" fact read off a DeepSeek page for the Qwen 4 question was condensed with Qwen 4 claims and the report called the model "V3.2 (Qwen 4)". Code now reduces the objective's names to families and keeps a claim for a question only if it names that subject or its page is about it; condense splits a group by subject and drops a sentence that names a subject none of its members names, a verifier's correction cannot bring in another subject, and a section writer sees only claims that fit its question. No model call; run m6 would have lost 12 of its 104 claims.
- **The engine no longer turns away a model that fits, or keeps one that was never checked.** Another model Ollama still held made the start read the card as short and sent the model to Ollama for good; Ollama now lets go of it when the card is short. A server whose GPU counters could not be read (no instance yet, or no PDH) was taken for a spilled one and killed; no reading is no verdict. A kept fit is held to the planner's reserve at the start too.
- **A model too big for the free GPU stays on Ollama, and the line says why.** Found live: a 12.8 GiB model on 11.9 GiB free went to Marlowe's llama-server with the no-measurement fallback (32k, one slot, f16) and the Windows driver paged it into system memory (46 tok/s read instead of 2,400); the engine now takes a model only when the planner fits it whole beside what is free, never for want of a GPU reading or an estimate, and a model that does not fit runs on Ollama with "X runs on Ollama: needs 13.6 GiB on the GPU, 11.9 GiB free". The server start re-checks the free memory (after Ollama let go) and a load that turns out not to fit is declined, not spilled; a declined model is tried again only once a GiB more is free.
- **A server the driver spilled into system memory is stopped and Ollama answers.** `--fit off` does not fail under the sysmem fallback, so after the server is healthy the engine reads its dedicated and shared GPU memory (PDH) and, when shared memory is well past the pinned buffers or the weights are missing from dedicated memory, kills it and serves that request on Ollama with a one-line notice.
- **A cold llama.cpp server is a load, with its real time, not "loaded in 48ms".** The call is announced before the server starts, so the turn shows "loading" while it spawns and the load line ends when the server is up; the reading line gets its tok/s and bar from the server's own clock.
- **Where projects run, `team` no longer lists a saved task a project replaces.** Found live (run 10): the description still offered `web-research`, so a small model picked it; the listing (fixed once per session) and the "saved tasks" lines of the refusal and of a missing `path` now drop what a project kind supersedes, by the same predicate as the refusal, which stays as the backstop.
- **The first Wake offers the memory models.** On a machine without them, onboarding asks "Install memory LMs? · 193 MB" (recall by meaning, not just matching words; keyword-only without), right after the name, or on its own for a user already named. Yes downloads on a daemon thread with the progress on the memory line ("installing memory LMs 42% (81/193 MB)") and loads the models without a restart; no is remembered in `onboarding.json` and the memory line says `marlowe models fetch`. A `cuda` build includes the five cascade graphs in the same question. Nothing downloads without a yes.
- **`marlowe models fetch [--cascade]` downloads the memory models.** Streamed to a `.part` file, checked against the sha256 the code pins, then renamed; a mismatch deletes the file and fails. Redirects are capped at five, https only, to Hugging Face hosts (or the host of `$MARLOWE_MODELS_URL`). `marlowe models path` points to it when they are missing; a file that is not published says where ("memory LMs not published at <url>: keyword only").
- **`scripts/fetch-models.ps1` falls back to Hugging Face, and `scripts/upload-models-hf.ps1` publishes the fine-tuned rerankers** to `devvexus/marlowe-memory` (hash-checked first; run by hand).
- **A saved team task a project kind replaces is refused where projects run.** `team{name:"web-research"}` with a project service answers that a research project replaces it and how to start one. Found live: told "a project replaces it", dawn still ran the old team task, whose agents asked 63 times in 45 minutes.
- **A quote that ends in a multibyte character no longer panics the analyst.** Locating a quote across `[L12]` markers took a character from the middle of one ("·"); the end is now one past the quote's last mapped byte.
- **A question that names no subject is searched with the objective's names.** "Under what open source licenses is each published?" had gone to the web as it stood and brought back music news and court orders; the question's own query now carries the objective's names (capitalised or with a digit: Rust, TUI, Qwen4), and the search planner is told every angle names the subject.
- **A plan's records always have a name.** When no field names a row (`name`, `*_name`, `title`, `*_id`) and none is marked `key_field`, code adds `name` first. Found live: a plan for "the three most popular Rust TUI libraries" collected stars, version and date with no library name, so rows were keyed by a star count.
- **A research turn goes to a project.** In a conductor session with projects, the first web search, fetch or arXiv call of a turn whose message asks for research (the same whole-word test the reminders use) is answered with the way to start one, every web call of that step alike; a `manage_project` call ends it, and the model may still search at its next step for one quick fact. Found live: dawn answered "Research the three most popular Rust TUI libraries ..." with thirteen web searches of its own, each an approval ask.
- **A report's records table is the rows that say something.** Rows merge by their name's letters and digits ("Kimi K3", "kimi-k3" and "Kimi-K3" were three rows), come only from pages rated Critical, High or Medium, a value that only says it is missing ("[Date not specified in excerpt]", "unknown") is no value, and the table shows at most 25 rows that carry more than a name, saying how many more the project file holds. A live table had listed sixty names, most with every field empty.
- **A writer sees each claim's date and uses every claim that answers its question.** A claim carries the newest publication date among its sources' pages, the writer is shown it, and asked for one sentence per answering claim (up to 12), the most recent first when the question asks for the latest. A live DeepSeek section had 25 verified claims, V4.1-Flash among them, and said two sentences about R1.
- **The projects block tells the manager how a plan reads well.** Each question names its subject, because a researcher reads it alone; a request about a set of things gets fields for the facts to collect, the naming one first.
- **A writer answers in sentences, each with the claims it rests on; code places the markers.** The section and answer forms take `sentences: [{text, claims}]` and code renders `... text [C3, C7].`, so a marker always sits inside the sentence it cites. Free prose put markers at line starts and on lines of their own, and the audit cut 24 of 30 sentences of a live report, most for markers that had come loose from their sentence.
- **One sentence per auditor.** With six to a batch, dawn gave verdicts that belonged to the sentence beside the one they were numbered for; each auditor now judges one sentence against its own passages.
- **A search query needs at least three letters.** A name of `[1,` had gone to arXiv as a query.
- **`enter_plan` is for code changes; a project's card is its plan.** Its description said to plan first when "the change is large", and dawn read a research request as large: twice it entered plan mode and wrote an `exit_plan` instead of starting the project.
- **Plan mode lets a project plan be made.** A project's plan waits for the user's approval of its card, so `manage_project` create, revise, status, list and checkin count as reads in plan mode; answers that send a project on are still refused there. The tool says its card is the plan (no `enter_plan` first). Found live: dawn entered plan mode for a research request and was then refused its own project.
- **A page the antivirus removes is left out by name.** Windows' "contains a virus" errors (225, 226) on a stored page become `StoreError::Quarantined` ("the antivirus removed this page as malware; it is left out"), and the analyst and verifier say so instead of "not in the project's files". Nothing tries to keep or hide such a page. Found live: Defender removed a cached search result as Trojan:JS/ChatGPTStealer.
- **The grammar limit is 1,999, measured, not guessed.** Ollama's bundled llama-server parses `maxLength: 1999` and refuses `2000`, so the clamp of the previous fix still failed every report writer live; the bound is 1,999 now.
- **A report says plainly which parts its writers could not write, and is never medium confidence then.** A failed section shows its question with "This section could not be written: <why>", a failed answer is listed under Checks, and confidence drops to low. A live report had come back as "medium" with no sections at all.
- **A project record is about something the page names.** A row's key (its `model_name`, say) must be words the page itself uses, matched however it is punctuated, as a claim's quote must be the page's words; the analyst is told to name each thing as the page does. Found live: dawn filled `model_name` with "Kimi/Kimilab" and "Qwen/Alibaba" and added rows for models a page never mentioned.
- **Web search works out of the box with no key and no paid API: the free agent searches take turns.** After SearXNG (when one runs), the web channel asks Parallel's and Exa's public MCP search endpoints, which serve agents without an account, alternating which goes first so neither free tier carries every query, then Marginalia's public API, then DuckDuckGo. A tier that refuses for load (HTTP 429, a rate or quota error) rests for its `Retry-After` or 15 minutes and the next one answers. DuckDuckGo served this machine a "are you a bot" page after three queries (lite and html alike), and nothing tries to get past that. The research network port gained a JSON POST (`HttpGet::post_json`, https only, no redirect, no credential); `free_search` in research.json turns the APIs off.
- **A project's records are keyed by the field that names a row.** `key_field: true` on a plan field picks it; otherwise the first `name`, `*_name`, `title`, `*_title` or `*_id` field, else the first. Keyed by `provider`, "the newest models" folded every model of one company into one row.
- **The lead and the writer see every round's questions.** A continuation plan holds only its new questions; the lead decided on that round alone, and a writer for an earlier round's question was given the objective instead. Both now read the project's question items. The lead is no longer told about "interns" (it wrote follow-ups like "Can the interns verify ..."), and a follow-up must be a question about the subject, never an instruction and never a rewording.
- **A forced form with a long text field no longer fails at the server.** llama.cpp refuses a grammar that repeats more than about 2,000 times (`maxLength: 4000` on the report sections), so every writer of a live project failed with `bad_request` before it generated a token. The grammar is given the largest count the parser takes; the reply is still checked against the full form. A cut text keeps its ellipsis inside the cap, so it passes the form it was cut for.
- **A conversation knows its running projects.** The turn tail names them (id, title, status, phase), so "is the research still running?" is answered from what runs, not guessed. A refused plan says nothing was created, so a small model does not go on to revise an id it invented. With no general web backend, a question's first web queries go to Hacker News, Wikipedia and GitHub instead.
- **Projects reach the conversation: the `manage_project` tool, the service behind it and the daemon wiring (stage D).** The manager writes a plan (objective, questions, fields) and `create` returns the card at once; a card parks the project with no thread held and no slot taken, and `answer`, `checkin`, `cancel`, `revise`, `reopen`, `status` and `list` are one short call each. `marlowe_project::service::ProjectService` makes, parks, resumes and recovers projects through a `ProjectHost`; the daemon (`project_ops.rs`) is the host: the conversation's model admitted without loading anything unseen, the crew's slot pool, the Mind as the memory sink, broadcast events, boot recovery of running and parked projects, and a relay of the result (`[crew · run project <id> · finished]`, the report path, tainted) that waits for the user's next turn when no model is loaded. Section 6 and the stage D section of docs/research/projects-design.md describe it and what differs from the first design.
- **The tool is `manage_project`, not `project`.** The verify group already owns `project` (build, test, lint); two near-identical names are a trap for a small model. It lives in the workflow group beside `team` (conductor only), its description is 530 characters and `persona/blocks/project.md` (456) is appended while it is live.
- **A plan cannot be approved in the turn that made it, and a tainted conversation asks before a project goes on.** The user has not seen the card in the turn it was made; once untrusted content is in the conversation, `approve`, `keep_researching` and `steer` ask for approval, so a page cannot approve its own plan.
- **Teams reminders point at projects when the daemon runs them.** Teams on: start a project for every substantive request without asking and for every research request; Teams off: a research request starts a research project (its plan card is the ask), other substantial work is offered one; a saved team task a kind supersedes (`web-research`, `deep-research`) is named as replaced. Without a project service the old Teams text is sent unchanged.
- **`marlowe project`.** `list`, `show` (the project JSON as saved), `view` (the shared renderer as text), `overview` and `card` read the files and need no daemon; `answer`, `checkin`, `cancel` and `reopen` go through it, so a project can be checked and steered before any screen exists.
- **Wire: `ListProjects`, `GetProject`, `AnswerProjectGate`, `CheckinProject`, `CancelProject`, `ReopenProject` and the `ProjectList` event.** The state events of stage A are broadcast now. `CrewSetup.projects` (`ProjectSetup`) is how the binary hands the daemon its keyless channels and corpus fetcher for projects.
- **Shutdown suspends projects instead of cancelling them.** `Control::suspend` stops in-flight calls and drops their results but leaves the project `running`, so the next start replays the journal; `RunOutcome::Suspended` is new.
- **The 32k prefix slices grow to fit the tool: persona and blocks 2,200 tokens, tools 7,400, total 13,000.** They were 2,000, 7,000 and 12,500 and exactly full; the A15 gates (`the_fitter_keeps_the_dusk_prefix_inside_its_budget`, `parity_a15_instructions_at_their_cap_reach_dusk_uncut`, `the_wired_dusk_prefix_fits_its_slices_in_a_repository`) pin the new numbers.
- **`docs/projects.md`: how to add a form, a phase type or a kind, and how to test one.** A short working guide beside the design; the architecture notes have a Projects section.
- **Projects research phases (stage C): `marlowe_project::research`.** The functions the research menu names: AttackVectors (the employee is told today's date and that its knowledge is old; code adds the question's own words, the names it suspects exist, date-worded variants and a year floor), search and fetch as two steps under a run-scoped network grant, Analyze (the model judges and quotes, code fills index, source, urls, credibility and relevance and drops any claim whose quote is not in the page), Extract, delta Condense, Verify, the lead and its checkin card, a Report whose cited sentences are re-read and audited, and Finish. Tested on a recorded world (nine pages, hostile page and hostile model answers, kill and resume to the same `report.md` bytes); nothing was run against a live model or site. See docs/research/projects-design.md, stage C.
- **A model never writes an address in a project: pages reach it with numbered links.** `[anchor](url)` becomes `anchor [L12]` and the page's link table is stored beside it; the analyst points at numbers, code looks the exact url up, a named reference resolves only through the page's own reference list, and url-shaped words are cut out of every model string. A claim's quote is located in the stored page (with or without the markers) or the claim does not exist.
- **A project reads public https pages the run found, under the grant the user gave by approving the plan.** `Grant` refuses http, raw and private addresses, a public name that resolves to a private one, a port other than 443, an address the run did not find and anything past the quota, asks the reader about every redirect hop and discards a page whose final address it would have refused; the quota is counted from the page items, so it survives a restart.
- **A prompt may carry the answer code already knows (`Prompt::canned`).** A claim whose quotes are gone from the stored page is `unsupported` and a question with no verified claim gets the fixed line, with no model call, no slot and no agent.
- **The engine owns only its own live numbers.** `Mutation::SetRunMetrics` sets tokens, running time and budget raises; `Mutation::AddFetch` counts page reads atomically from task threads, so parallel fetches no longer lose each other's counts to the engine's save.
- **A project whose first step fails for most questions asks the user instead of writing an empty report.** AttackVectors is an `important` step, so the failures checkin applies to it too.
- **The text helpers of research v2 live in `marlowe-research`.** Quote location, citation markers, sentence spans, passages, query text and the standing-word rewrite moved (`text`, `queries`, `standing`) and the crew re-exports them unchanged; the v2 differential, parity and supervisor tests are green and unchanged.
- **The corpus fetcher and the keyless channels serve projects.** `ProjectPages` reads through the corpus (robots.txt, spacing, Edge) with the grant asked first on every hop, `ProjectWeb` searches through the registry, `project_research(home, settings, memory)` builds the dependencies; they are not called until the `project` tool exists.
- **Projects phase engine and employee runner (stage B): `marlowe_project::engine`.** Phases are data (`registry/phases/*.json`: fan-out, code step, delta merge, gate; `spec::validate_menu` checks the menu); an employee is one fresh-context, tool-less model call forced into its form by the engine's grammar, parsed and validated again in code, retried by a table (a cut reply resends the same prompt with the limit doubled, an invalid one appends the reply and the errors, a form rule rejects with its own words) and recorded `failed` with a harness-written reason that holds no model text. The scheduler is level-triggered over a light index of the state: phases overlap where their data streams, tasks run drain-first with round-robin across questions, fetch and search run on lanes of their own while every model slot is held, a merge fires at 25/50/75/100% of the watched step and sends only what is new, and every finished task is journaled before it touches the state so a restart replays the journal and asks no model and fetches no page twice. The engine parks (its thread ends) on the plan card, on a checkin the lead or the user raises, and on a budget or failures checkin; cancel marks unfinished items `cancelled` and saves; a function that panics fails its task. Generic functions cover the plan card, approval and its run-scoped network grant, checkins and continuation rounds; a kind, a form and two phases registered as data run and draw with no code. Tests run the real research menu on fake models (3 engine, 16 scheduler tests) and an ignored test ran the runner once against a CPU llama-server on `marlowe-mini:4b-super`. The `execute` branch, the `project` tool and the research functions are stages C and D.
- **`ChatRequest.think_budget` bounds the reasoning of a forced-form call.** The llama engine sends it as `thinking_budget_tokens` (measured on CPU: without it a trivial form spent a whole window reasoning and the answer never came); Ollama and the cloud providers ignore it; it is absent from the wire when none, and the agent loop still sends none.
- **A project's employees take the crew's model slots (`marlowe_crew::project_gate::ProjectGate`).** It implements the engine's `ModelGate` over a run's `StepHooks::before_call` and `after_call`, so a project shares the one pool of `crew_slots` with every run, the commit-memory check, the GPU hold and the run's budget; nothing starts an engine from a crew run yet.
- **Projects core built (stage A): the `marlowe-project` crate.** The plan (validated for a small model, three errors at most, each with its fix), forms that are both the JSON Schema an employee is forced into and the description of how each field is drawn (badge, link, table, progress, meter, duration, agent chips), 14 research and engineering forms and a kind registry as JSON files, the project state document, mutations that return JSON-pointer patches and refuse a `done` item whose data breaks its form, one generic view-model and plain-text painter that draws a research source, an engineering experiment and a kind nobody registered from their JSON alone, an overview rolled up from every project's JSON, a store (atomic `project.json`, journal, content-addressed sources, archive, reopen, disposal, the `projects` index in `cowork.db`) and a single-writer state actor. `marlowe-proto` gains the patch type and `ProjectUpdated`, `ProjectState`, `ProjectGateRaised` and `ProjectGateAnswered` events. The JSON Schema validator moved from `marlowe-workflow` to `marlowe-contract` and is re-exported, so nothing else changed. Nothing runs a model yet (stages B to D).
- **Projects design reviewed and tightened.** The plan now needs only an objective and question strings (fields are one key each, the rest defaulted by code), live item fields read from `live.*` so the engineering example renders from its form alone, Plan, Report and Finish are declared like every other phase, merge passes replay from their recorded membership, and build stages A to D are split into sub-steps that can be tested one by one.
- **Projects design written: a plan, phase and employee model where the manager only designs and single-task models fill forced JSON forms.** docs/research/projects-design.md specifies the schemas (plan, project state, AttackVectors, Analyze, claims, Verify, Report, Checkin), the display-hint vocabulary a generic renderer draws any project from, the phase engine, constrained output (measured on a CPU llama-server: the grammar does not cover thinking tokens, a per-request thinking budget does work, a truncated reply is not valid JSON), storage, the manager tool, and build stages A to D; it supersedes deep-research-teams-design.md. Nothing is built yet.
- **A message that names a saved team task gets that task named back to the model, and a `path` that is no file is answered with the saved tasks.** The Teams-on reminder (a conversation-tail line, so the cached prefix is untouched) now adds "the user named a saved team task: `x` (what it does; args ...); run it with team{name, args}, no script, no path" when the message holds a saved task's name (spaces for dashes, any case; a one-word name only when called a task or workflow). `team` given a `path` that is not a file runs a saved task whose name the file stem is (`web_research.star`), and otherwise answers with the saved tasks and how to run one by `name` instead of a bare "cannot read".
- **The saved-task list is a few words per task, because the tool slice is full.** Each line is the task's META `summary` (new, optional; the description cut when there is none) and the names of its META `args` with `*` on required ones (`web-research: cited web research report; args topic*, questions, file`); the `team` description gives up the sentences the list now makes redundant, so a local conductor with an MCP server still lists the server's tools instead of hiding them behind `tool_search`. A parse error blames a bracket or string only when it begins at or before the line the parser stopped on, and names the earliest bracket left open (the one that swallows the rest). `team` also takes `args` sent as a JSON string, and an input sent beside `name` instead of under `args` is told where it goes.
- **A finished team task hands the user its files and its whole result, without waiting on a merge.** The result now lists the files its agents made, first, by full path (a run in a git workspace names them in its worktree, "no approval needed to open or send them"; the merge is offered as an option, and a run with no git workspace has them copied to `<home>\output\<task>-<run>\`), a text result is shown as text instead of an escaped JSON string, and a result longer than 4,000 characters is also written whole to `result.md` beside the journal and the relay points at that file instead of at `marlowe crew show`, a command the conductor cannot run. `send_file` takes files from a crew run's folders (output, scratch, worktrees, workflow runs) as well as the workspace, and the notify tools (`notify`, `send_file`, `notices`) are now offered to a conductor with no workspace, which could not be sent a file at all before. The relay says to send the file when the user asked for it to be sent.
- **A relay of a run that just ended no longer waits for the user's next message.** The "is not loaded, and background work never loads a model" refusal stranded results the user had asked for while the model's 300 s keep-alive had expired. A relay for a run that ended while the daemon was up now starts Ollama if it is down and loads the conductor's model when it fits (it never asks and never loads one that does not fit), the same as a crew agent would; relays caught up at start stay background-only. The loaded-check also counts the parallel engine's model when Ollama does not answer (it used to report "the engine did not say which models are loaded" and refuse).
- **The model is told which saved team tasks exist, and a refused script costs it its turn.** The `team` tool's description now lists the saved tasks (built-in, the user's, the workspace's: name, one line, the `args` each takes from its META `args`), read once per session so the tool list and the prompt cache hold; the Teams reminder and the authoring skill say to run a named or fitting saved task by `name` and `args` and write a script only when none fits. A name that is not exact still finds its task (case, spaces, underscores, a trailing "team task"), and an unknown one returns the closest names and the whole list. A call whose script the checker refuses now gets the checker's answer before any "run in parallel" note (the note used to promise a run a script that could not run), and refusals are counted per turn: at the 3rd the answer says to stop writing scripts and names the closest saved task with its args, at the 5th the turn ends with a plain message to the user. A shipped skill that was never edited is refreshed on start (the preview home still held a copy three versions old); an edited one is left alone.
- **The loop guard counts a tool's failures by kind, and a tool can end the turn.** An outcome can carry an error class (`ToolOutcome::error_of`), and failures of one class count together however each is worded or numbered, so a checker that words every refusal differently (28 refused team scripts, longest identical run 3) still trips the repeated-failure note; a tool can also ask the loop to end the turn with a message to the user (`EndTurn`), honoured after the step's results are recorded. Both are generic: `team` uses them in the next change.
- **The team script checker says what is wrong and where, once.** A parse error now also names the bracket or quote behind it (`the ( opened on line 12 is never closed`, `the triple-quoted string opened on line 20 never closes`, `] on line 17 comes before the ( opened on line 14 is closed`) with a balanced example, cuts the 50-token "expected one of" list to a sentence, and says when a line must be indented; the JavaScript hint appears only when the failing line itself is JavaScript (the words "bullet points" and "=== Data ===" inside a prompt used to trigger it); `while`, `try`, `class`, `del`, `assert`, `with`, `global`, `yield` and `else if` get their Starlark equivalent. A script with no `def main` gets one message with a skeleton instead of one per `agent()` call, and a call left outside `main` by a missing indent is blamed on the indent (`main's body ends at line 14`). `parallel` also takes prompt strings (`parallel(["first question", "second question"])` is `parallel([lambda: agent(...), ...])` without the nested brackets that most refused scripts got wrong). The starlark 0.13 dialect has no option for `while`, `try` or chained comparisons, so none was enabled.
- **`web-research` ships as a built-in team task.** Run it by name from any workspace (`team{name: "web-research", args: {topic}}`): one researcher per sub-question in parallel, each claim checked against its page in parallel, one writer that saves the cited report (claims numbered, References list) to `research/<topic>.md`. It is listed with the other saved tasks, and a workspace `.marlowe/workflows/web-research.star` overrides it. A local model could not yet write this script itself reliably; the rehearsed one ran 35 agents with up to 6 slots busy.
- **`agent` subagents on a local model run in parallel, like crew agents.** They used to queue one at a time per session (one foreground, one background) even on the llama.cpp engine with several slots. They now take slots from the crew's pool for that model (its slots less the conductor's, foreground and background alike), so subagents and crew together never exceed the real slots or touch the conductor's; with one slot (Ollama) they share it and the agent's line says "waiting for a model slot" and why. Cloud lanes are unchanged.

### Prompt cache

- **No test, default or comment names the cyber model.** The prompt-cache audit runs only dawn and mini by default, store-resolution tests use a neutral model name, and a stray run of spaces in a cut-off tool-call message is a single space.
- **Preserve-thinking is worked out per model from its own chat template.** The engine renders a probe conversation through llama-server's `/apply-template` once per model file digest (kept in `llama-thinking.json`) and learns whether the template keeps earlier thinking, keeps it behind a switch (`preserve_thinking`, `clear_thinking`; then exactly that switch is set), or drops it at the next user message with no switch (dawn and mini); every reply goes back with its `reasoning_content` as produced and no template or model file is touched.
- **A template that drops thinking is followed, and its cost is taken off the user's path.** When a conductor turn ends the engine renders the history plus a placeholder user message with the model's own template, cuts at the last special token before the placeholder and reads that prefix into the conversation's slot in the background (`/completion`, nothing generated); a message sent meanwhile waits for the read on the same slot and then reads only itself. It is decided by comparison with what the cache holds, never by model name, and skipped after a tool call and for crew agents.
- **dawn and mini run on the parallel engine through llama.cpp's own route** (the GGUF's chat template with `--jinja` and llama.cpp's tool-call parser); a manifest renderer or parser no longer keeps a model on Ollama when the model file has its own chat template, and `{{ .Prompt }}` counts as no template. The per-model switch still sends a model back to Ollama.
- **The conductor's token capture is used only when it is complete.** llama-server's chat stream attaches a generated token to the chunk its parser emits and never sends the tokens the parser swallows (`</think>`, tool-call markers), so the captured text was short on every thinking or tool-calling reply and the guard logged false cache violations; the text is now trusted only when its token count matches `predicted_n`, and a server that fails the check is not asked again (the template's own printing stands in). The audit harness counts a request after a user message as clean when the engine's read-ahead held the thinking-less prompt and only the new message was read, and takes the engine's eligibility from the model file's template.
- **A local model's prompt cache no longer breaks except at a compaction.** History goes back exactly as produced on every provider path: tool-call arguments in the order the model wrote them (`serde_json` `preserve_order`; the loop still runs the canonical call), reasoning on every assistant message, tool results and whitespace untouched, an interrupted or repetition-cut reply stored as generated, a call finished before an interrupt answered `Not run`. The system blocks and the tool list are frozen on the conversation and stored with the session (a late MCP tool is announced on the newest message and joins the list at the next compaction), and the tail and every injected message are written before the call, so a restart sends the same bytes. Compaction fires at 90% of the window judged on the last real prompt size, masks old tool results only as part of it, and its summary call is sized by the real token rate and halves its transcript when the server says it does not fit.
- **Marlowe's own llama-server keeps each conversation's cache across a stop.** Before it stops a server (restart, idle unload, model switch) the engine saves every used slot (`--slot-save-path`, `/slots/{id}?action=save`) and restores them when the same model loads in the same shape. A plain `marlowe shutdown` no longer unloads an Ollama runner (a window close still does).
- **The engine asks the model's own template to keep earlier reasoning** (`preserve_thinking`, `clear_thinking`; a template without the switch ignores them), renders each request through `/apply-template` and checks it against the previous prompt plus its reply. A template that drops reasoning anyway (Qwen's, with no switch) is logged as a `template-drop` note; anything else outside a compaction is a `PROMPT CACHE VIOLATION` in `daemon.log`, and the prefix-guard tests fail on it.
- **`eval/prompt_cache` audits whether any request rewrites what a local model already read.** It drives the real daemon (throwaway home, temp git repo) through a scripted conversation of thinking, multi-argument and nested tool calls, a tool error, a memory write, an interrupt, a steer, an outside file change, the Teams toggle and a daemon restart, with a tee in front of Ollama or Marlowe's own llama-server. The server's own numbers say how much of each prompt came from cache; every request that did not reuse the whole previous prompt plus the reply is named with the first differing byte, the message that produced it and the cause. `--templates` reads each model's own chat template from its GGUF and tests what it does with earlier reasoning.
- **Compaction waits for the window, not for two thirds of it.** The trigger held back the whole reply cap (a quarter of the window on a local model, 13k of 53k), so a conductor compacted at 36k and threw away a 40k-token cache that had room to grow; it now holds back at most 4k and the request's own reply cap shrinks to the room the prompt leaves. A masking chunk keeps fewer than eight old tool results when they are big (a quarter of the window at most), so a step of fetched pages is not as full after the chunk as before it.
- **A reminder after a tool result rides on that result for a local model.** Qwen-family templates drop all earlier thinking at any user message, so the loop guard's repeated-call note, the error and promise nudges and every middleware `after_step` reminder each cost a conductor 10-28k tokens of re-reading mid-turn (seen live on dawn); they are appended to the step's last tool result, which no request has carried yet, instead of becoming a message of their own.

### Parallel local engine

- **Marlowe runs a local model on its own llama-server, with several slots.** For a model Ollama hands to llama-server whole (its manifest has no renderer, parser, template, draft or projector layer: `marlowe-dusk:22b-r1.5`, `marlowe-red:9b`, `marlowe-unhealed`), Marlowe starts Ollama's bundled `llama-server.exe` itself (hidden, in a kill-on-close Job Object, credentials scrubbed, output in `logs\llama-server.log`) with N slots of the planned window each, the same flags Ollama uses, q8_0 KV per slot (no shared pool), `-ngl 99 --fit off` so a misfit fails at load. Ollama is asked to unload the model first, so it is never in memory twice; idle unload follows `OLLAMA_KEEP_ALIVE` (five minutes by default). Models Ollama renders itself (the dawn, mini, valiance, qwen3.5 and 27B tags) stay on Ollama exactly as before, and `MARLOWE_LLAMA_ENGINE=0` keeps everything there.
- **Tool calling is unchanged.** The request is the one Ollama sends such a model (`/v1/chat/completions`, the GGUF's own chat template, the model's `.params` over Ollama's defaults, history sent exactly as produced with its thinking) and llama-server parses the tool calls; the reply goes through the same folder, repair and leak recovery as Ollama's. No parser was written.
- **The conductor keeps slot 0.** A request carries a lane; the conductor's conversation is pinned to slot 0, each crew conversation sticks to the slot it last used, so crew calls never evict the conductor's prompt cache. Crew agents run at once on the other slots.
- **The planner chooses the slots.** Without a saved policy an engine model gets six slots when each still has 16k after a GiB of reserve (measured: the plain estimate was 1.1 GiB under what the server took), else fewer slots with more each; the planner box says which engine serves the model and what each agent gets, `e` there turns the engine off or on per model, and the model box shows `llama.cpp` with the slot count on the meter. Saving a policy for an engine model restarts no Ollama.
- **The read line uses llama-server's own numbers.** Prompt tokens, cached tokens and read time come from its timings, and the read shows live progress (`prompt_progress`) while it happens, with nothing estimated. A load is a live background-work line; an idle unload is said once.
- **Verified live (2026-10-22, RTX 4080 SUPER, `marlowe-red:9b`, real daemon):** all six slots processing at once (conductor on slot 0, five crew agents on 1 to 5), the conductor's second turn read 6,565 of 7,616 prompt tokens from its cache while the crew ran, tool calls worked, and everything was stopped afterwards with Ollama left running and nothing loaded. Not verified: the dawn and mini models (they stay on Ollama), long runs, the idle unload against a real server, and the planner's new reserve against a real load.
- **Review fixes.** Applying an Ollama server setting restarts `ollama serve` hidden with its output in Marlowe's log, never the tray app; stopping, switching or idling out the llama-server happens under the engine's lock, so a new load can never overlap the old server still holding the GPU; the server runs without `--context-shift`, so it never silently slides a conversation's window (an overflow is a clean error and the loop compacts); and the planner's one-agent fallback is kept like its other choices, so it is not recomputed (or changed) on every request.

### Compaction

- **After a compaction the model is told what happened.** The summary used to ride in the system prompt in a first-person voice with a one-line label, so the model took it for part of its instructions and could not tell who wrote it (it called it "the condensed system prompt"). It now arrives as one user-role message that says the harness compacted the conversation because the context was full, that the assistant wrote the summary and the user did not say any of it, that the latest user message and recent steps follow verbatim, and not to re-ask or re-read what the summary covers; the pinned working set sits after it, labelled as kept verbatim. The system prompt no longer changes at a compaction.

### Ollama start

- **Marlowe starts Ollama headless, never the desktop app.** When Ollama is not answering, Marlowe now always runs `ollama serve` hidden and detached (your saved environment applied, credentials removed) and keeps its output in the size-capped `logs\ollama-serve.log`, so the read line gets Ollama's real numbers. A running Ollama or app is used as is.

### Tests

- **Five daemon tests no longer depend on timing.** The subagent-approval interrupt test asked for a foreground agent but got the background default (so its turn had already ended); the crew relay tests let a fast run land inside the turn as a steer, or unloaded the model before the run started. Each now holds the run until the state it needs is reached.

### Composer and transcript notes

- **Ctrl+Backspace and Ctrl+W join lines.** At the start of a line they delete the newline and then the word before it, as editors do.
- **A turn that compacted or loaded a model and then said nothing still ends with "ended without a reply".** The engine's own lines no longer count as the model having spoken.
- **A memory write that finishes during a later turn is kept on the turn that wrote it** (its usage footer), not dropped.
- **A held report's line is stored with the conversation** (`session_notes`, sent as `SessionNotes` ahead of the transcript), so it is still there after the window is closed and the session reopened.

### Team agents

- **"Allow for the session" on a tool a team agent asked for covers the run's other agents.** A crew run answered `AllowForSession` as a plain allow and each agent kept its own list, so one team task of 35 agents asked 131 times for three tools (`web_search`, `arxiv`, `web_fetch` on each new host); the answer now goes back as given, and the run's agents share the tools and hosts they were allowed at each step boundary. A tripwire still asks every time.
- **`task_output` on a team run returns one line per step, not one per streamed piece.** The run's transcript file holds every streamed text piece on a line of its own, and a poll of a running team returned 32k characters of `{"text":"I"}` lines (about 10k tokens), twice a minute, which filled a 53k window and made the conductor mask its history three times in a minute; the pieces are joined and a long step shows its last 500 characters.
- **A workflow agent's structured-answer repair no longer thinks.** The finalisation call that turns an agent's last report into the schema ran at low effort, and a thinking model spent all 4,096 tokens reasoning about the JSON and returned nothing ("did not return JSON: EOF" for 3 of 15 checkers in one live run); it runs with thinking off, since the schema already constrains the output.
- **`team` with a `path` that does not exist and the name of a saved team task runs the saved one.** dawn passed `{name: "web-research", path: ".marl owe/workflows/web-research.star"}` (a space inside the folder name), `path` outranks `name`, and the call failed three times while the saved task sat there; the result now says the path was not found and which saved task ran.
- **A team task started with no arguments gets `args = {}`, not null.** A saved team task run by name (`team{name: "web-research"}`) failed at its first `args.get(...)` with "NoneType has no attribute get" and the conductor spent a turn patching a working script.
- **A team task that ran no agent says so, and a script that would run its agents one after another is sent back once.** dawn's scripts stopped part-way (a `main` that logged and returned) and the notice read "done"; the result now says no agent ran and the script is probably unfinished. A script with three or more `agent()` calls and no `parallel()` or `pipeline()` (six researchers in a row, where the user asked for a team in parallel) is returned unrun with how to fan out; the same call sent again runs as written.
- **A call cut off by the output limit says so, and ten identical failures end the turn.** dawn wrote a 13k-token script into one `team` call, was cut at the reply cap, was told the arguments "were not valid JSON", and called `team{}` 91 times in one turn; the refusal now says the reply stopped at the output limit (with the tokens it wrote) and to make the call much shorter, the skill says to keep scripts to a few dozen lines, and the same call failing the same way ten times running stops the turn with that said.
- **A research team task no longer starts with a hunt through the workspace.** The `team-task-authoring` skill said to scout the workspace first; for web research dawn spent its turns listing directories and reading old files. It now says research has no work-list in the workspace (write the sub-questions, one `web_search` for a map) and carries a checked worked example (researchers per sub-question, a checker per claim, one writer given numbered claims and told to end with a References list, `agent_type = "researcher"` so the agents get the reading and searching tools and no shell).
- **The script checker refuses a function or `META` given twice.** A script ending in `def main(args): pass` after a real `main` passed every check and ran zero agents; the error names both lines.
- **The loop guard tells a new mistake from the same one when a checker answers.** The `team` tool's refusal starts with the same header every time, so three different Starlark errors in a row were reported as "the same failure 3 calls in a row" and the model gave up; the first two lines of an error now decide.
- **`team` with nothing to run names the `.star` files the workspace holds.** dawn wrote three scripts and then called `team{}` eight times; the refusal now lists them and says to pass one as `path`.
- **A team task's `agent(model=...)` is honoured.** A name that is in the model library or Ollama's local models (added to the library) runs that agent when the planner says it fits beside what is loaded; an unknown or unfit name runs it on the conversation's model, with a note on the agent's result and on the run (as for an unfit crew slot). `inherit` keeps the role's model. `effort=` already reached the request and is tested. Tests use scripted models only.

### Workspace paths

- **A workspace path is made real when it is set.** `~` is expanded, a rooted path with no drive (`/Projects/MSFFN`) is found on the home or working drive or under home, the result is absolute and canonical (no `\\?\` prefix), and a path that does not exist or is a file is refused with the reason (`marlowe_proto::workspace`). The picker keeps its `~` display form apart from the stored path. Sessions already stored as `~/Projects/MSFFN` or `/Projects/MSFFN` are rewritten when the daemon starts.
- **A missing workspace is named once, plainly.** `bash`, `monitor` and `git` say "this session's workspace <path> does not exist — set it in the workspace picker" instead of "cwd ... is not a directory", so the model stops hunting for the folder.
- **The workspace picker completes paths.** Typing a path lists the folders under it filtered by what is typed, then recent workspaces, `~` and the drives (read on a worker, capped at 12 rows). Tab takes the only match, else the common start, else the selected row; the arrows move, a click or Enter sets it, and a path that does not exist stays open with the reason under the field.

### Prefill progress

- **The read line is Ollama's own numbers, never a guess.** The runner's output (`server.log` for the app; a size-capped `<home>\logs\ollama-serve.log` for an `ollama serve` Marlowe starts) is tailed read-only and matched to the request in flight, so the strip shows `reading 12.6k tok · 6.6k cached · 2,600/6,000 new · 96 tok/s ━━ 43%` with no `~`, and a cache miss shows as `0 cached`. With no output to read (a server started by hand) it shows tokens and elapsed only. `prompt_eval_count` is the whole prompt, so a read with no log has no split and no rate, and the stored prefill rate learns only from a runner-timed full read or the first call after a cold load; the old stored rates are forgotten.

### Prompt cache

- **A local model no longer re-reads the conversation on every message.** The environment block (the clock to the minute, the repo's dirty count and last commit) and the retrieved memories sat at the end of the system prompt, so every turn changed the system prompt a few thousand tokens in and Ollama's common prefix ended there (~7,000 of 12,611 tokens on `marlowe-dusk:22b`). They now ride on the turn's own user message (the `cache_stable` policy, now the default; `[context] cache_stable = false` in `settings.toml` turns it off).
- **The memory profile rides in the tail too**, on the first turn and again only when it changed (a `remember` used to rewrite the system prompt); an emptied profile is said once.
- **What a turn carried is stored with the session.** The per-turn tail, the Teams note, the prompt sections (instruction files, skills, repo map) and the reminders a hook put ahead of the prompt (changed files, job output) are saved, so a session loaded again after a restart, an idle eviction or a rewind sends the bytes its earlier requests did. Replay hides those reminder rows.
- **The daemon log names the section that broke the prefix.** When a local model's request does not extend the session's last one, `daemon.log` says `prompt cache break in session ... system block N / tool X / message N part M changed: was ..., now ...`, and `N other request(s) used the <model> slot` when another request (a subagent, a crew agent, a title) replaced the one-slot cache. Compaction does not log it. `crates/marlowe-daemon/tests/prefix_guard.rs` runs memory writes, file edits, commits, a Teams toggle and a daemon restart through the real daemon and request builder and fails on any break.

### Live strip

- **Nothing on the live strip is shown twice, and it is one line.** The strip is only the current activity at the bottom of the conversation: read and thinking are separate lines (thinking replaces the read line), the thinking block in the transcript is a fold handle (`reasoning`) while the strip carries the count and clock, a running tool is named once (in the transcript), a load or compaction is one line with one clock, and recall stages use that same line.
- **The read stats live under the opened thinking block** (coloured, estimates keep their `~` until the real numbers arrive); the thought header no longer carries a `read › thought` prefix.
- **A load, a compaction and the memory write become dim lines in the transcript** (the memory write after the reply it belongs to) instead of strip rows below the activity.
- **The title bar no longer carries a second clock.** The strip owns the one clock of what is happening now; the turn-long `thinking · 2m50s` beside it read as a second, contradicting timer.

### Background work

### Prompt cache

### Live phases (protocol and instrumentation)

- **One event family for every named step** (`marlowe_proto::phase`): `Event::Phase{kind, state, stage, done/total, rate, ms, est, detail}` for sending, setup, admit, prompt, recall (per stage), fit, compaction, wire and the memory-write tail. `Start`/`End` are ordered and replayed; `Progress` goes through `Bus::publish_ephemeral` (seq 0, not in the ring, never drops a client). Additive: no `PROTO_VERSION` bump, unknown events are skipped by old readers, unknown kinds decode as `Unknown`.
- `Recalled` also carries `total_ms`, per-stage `stages` and `abstained`, and is sent when nothing was recalled. `Event::TurnTimings` (spans, TTFT, harness overhead `enter_to_wire_ms` / `token_to_bus_ms`) goes out just before `TurnFinished` and is stored per turn (`turn_timings` table), replayed on `StoredTurn.phases`/`numbers`. `Request::Ask` takes the client's `client_ms` (Enter).
- **Retrieval observed, not changed.** `StageProbe::progress` (default no-op) is called at chunk boundaries in dense, gate and rerank; the Mind's `LiveProbe` times stages (the clock lives there, not in `marlowe-memory`) and streams them throttled to 8 ms. A test asserts the injected set, scores and order are identical with the live display on and off.
- Agent loop: `AgentEvent::{Phase, CallStarted, FirstToken}`; compaction reports estimated progress and no longer fails silently (`End{detail:"failed"}`). The Mind's write tail (`MindEvent`) reports ingest, embed and index.

### Live phases (provider timings, load meter, prefill estimate)

- `Usage` carries the engine's own `prompt_eval`, `load_ms`, `prefill_ms` and `decode_ms` (Ollama's `*_duration` fields, ns to ms; other providers leave them `None`); `StreamEvent::Sent` marks the request leaving, after the model metadata and body. Old frames still parse.
- The loop closes `Wire`/`prepare` at the send and opens `Prefill` (our prompt estimate, `est`); `Usage` ends it with the engine's counts, ms and rate, so the turn's `read` (new, cached, ms) is real. A failed call still closes it.
- The daemon's `live::Watch` thread (alive only while the engine is silent): cold-load progress from the runners' GPU-memory growth against the planner's predicted bytes (`est` total, never full before it ends, no bar without per-process data), prefill progress from the stored `prefill_tok_s:<model>` (capped 99%, nothing without a stored rate), and `waiting for the GPU - crew run <id>` only when a crew run streams on the same model. Prefill and decode rates are re-measured after every call into `hw_calibration`.
- Spans start where their `Start` landed; `Load`, `Prefill` and `Wire` stages nest under `Wire`.

### Live phases (frame engine)

- **The screen draws at the display's refresh rate while anything is live.** `marlowe_os::console::display_refresh_hz()` (primary monitor, `EnumDisplaySettingsW`; 0/1 or no answer is 60) sets the rate; `marlowe-tui/src/pacing.rs` decides when a frame is due: the first event after a quiet spell draws at once, a burst becomes one frame per refresh, a live turn or the voice ticks at the refresh rate, a still screen once a second, and the boot keeps its 30 fps. ### Context and hardware planner
